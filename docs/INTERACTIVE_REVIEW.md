# Interactive account review

An automatic negative or TextAd edit is not the full set of improvements.
The owner can ask a natural-language question, or use native `/yd review` to
read a compact report without a model. Its action buttons only prepare a single
decision card. `/yd review fresh` collects a new report and returns the outcome
to Telegram, without applying ads or publishing a batch of proposals.

Evidence comes from one dated snapshot. Partial campaign coverage, stale data,
future starts, the primary purchase goal, actual network clicks and unsupported
billing are separate facts. Course knowledge cannot establish account facts.

For shopping ads, compare the actual default text with its own current YML
filter. A copy change is owner-only, never a scheduled autonomous edit. A live
placement inconsistent with the saved plan blocks that edit. Offer one advisory
per campaign; approving the advisory changes neither the plan nor Direct.
`NETWORK_DEFAULT` with missing network placements is not `SERVING_OFF`. Collect
the network placement report when the setting allows networks or the ad report
actually observed network delivery during the historical period.

The read-only refresh reports observed facts even if analysis output is
invalid. It does not reuse a previous run's facts as the current result.
Signed Direct ad IDs stay server-side as Python integers; Telegram passes a
short opaque proposal key and the snapshot ID rather than a JS number.

The placement breakdown is collected when live settings or historical traffic
indicate network delivery. An absent response block is not proof of zero
network traffic. The separate placement-decision card is advisory and cannot
update bidding, feed filters, or the ad text. A preview reports its accepted
and rejected idea counts separately and never claims to have published cards.
