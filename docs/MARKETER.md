# Полуавтоматический маркетолог

## Границы первой рабочей версии

Реализован независимый цикл: данные Директа и Метрики -> проверка достаточности -> один вызов аналитика -> отдельные Telegram-карточки -> решение владельца -> точечное применение -> проверка API -> последующее наблюдение.

Аналитик рассматривает экономику, Поиск, РСЯ, креативы, посадочные, ассортимент и эксперименты. Он не обязан выдумывать предложение для каждого направления. Нет CRM, маржи, возвратов и подтверждённых оплаченных заказов: прибыль/ROI не рассчитываются. Поддержка всего маркетинга как гарантированно автономной замены человеку не заявляется.

Автоматически после подтверждения поддерживаются:
- одна полная наблюдаемая минус-фраза в одной группе;
- изменение текстовых полей одного существующего TextAd;
- одно значение CPA или недельного бюджета одноголевой PAY_FOR_CONVERSION, не более 20%, при достаточных подтверждённых конверсиях.

Другие решения (новые кампании, пакетные/многоцелевые стратегии, ретаргетинг, исключения площадок РСЯ, изображения, товарный ассортимент, посадочные, CRM) оформляются как отдельные **ручные планы**. Их одобрение не выдаётся за выполнение API. Прежние интерактивные возможности бота сохранены; владелец может отдельно поручить выполнить согласованный план. В новых карточках нет автоматического создания/остановки/перезапуска кампаний.

## Расписание и данные

- `yandex-direct-marketer.timer`: понедельник, 12:00 Europe/Podgorica. Не используется OpenClaw heartbeat или частый LLM cron.
- Минимум семь дней между попытками. Первый запуск выполнен при установке; ближайший календарный запуск может быть пропущен, если семь дней ещё не прошли.
- Окна: последние 28 зрелых дней и предыдущие 28. Последние семь полных дней и сегодня исключены. Эти параметры меняются в `backend/marketer/policy.json`.
- До вызова модели: >=30 кликов или >=2 числовых конверсий; повторный анализ требует >=20 новых кликов или изменения конверсионных данных. Сбор API без модели расходует API-квоту, а не токены модели.
- Все активные/приостановленные Unified Campaigns, если список campaign_ids пуст. Отчёты привязаны к покупке 352606262, счётчик 99041859; дополнительно собираются фактические цели стратегии.
- Директ: атрибуция кампании. Метрика: lastsign. Числа разных систем не суммируются.
- Нельзя считать прочерк `--` нулём: такие конверсии сохраняются как неизвестные. CPA не рассчитывается по неполному набору. GoalTotals хранит отдельные суммы числовых достижений каждой цели.
- Пагинация entities и Метрики обрабатывается полностью, sampled/rounded Метрика отклоняется. Отчёты Direct 201/202 ожидаются с retryIn в пределах ограниченного числа попыток.
- Полный снимок хранится в SQLite. Модели передаётся ограниченная выборка лидирующих по конверсиям/расходу/кликам строк и число всех строк. Это явно помеченная выборка, не полный просмотр всех запросов/объявлений.

## Карточки

Каждая карточка содержит кампанию, точное действие, обоснование, числовой контекст и период, гипотезу, метрику оценки и риски. Кнопки: одобрить, отклонить, изменить, отложить, подробнее.

- `marketer_revise` меняет только указанную карточку и увеличивает revision. Старые кнопки одобрения перестают действовать.
- `/yd` обрабатывается нативным плагином OpenClaw без вызова модели. Проверяются канал, allowlist, Telegram sender_id владельца и отдельный ключ решения. Инструмента одобрения у модели нет.
- Повторный клик не повторяет запись. Изменения параметров извне требуют новой карточки. Добавочные минус-фразы других карточек не затираются.
- Отложенная карточка не блокирует другие и не рассылается заново навязчиво. Через семь дней исходное подтверждение истекает; для дальнейшего применения нужна новая версия с актуальными данными.
- Отклонённые/ожидающие/применённые действия дедуплицируются по кампании и точному действию в течение 90 дней.
- Неоднозначный ответ после записи переводит карточку в `uncertain`. Автоматического повтора нет: сначала нужна ручная сверка.
- `advisory`: одобрение -> `accepted_manual`; только отдельная отметка владельца -> `completed_manual`.
- После применения точечных изменений наблюдение начинается через срок карточки плюс лаг конверсий. Малая/неполная выборка откладывает вывод до 90 дней. Сравнение на уровне кампании наблюдательное, не A/B-доказательство причинного эффекта. Автоматический откат не выполняется.

## Инструменты интерактивного бота

`marketer_status` -> последние запуски и карточки.
`marketer_context` -> компактный снимок и история.
`marketer_proposal {id}` -> полная карточка.
`marketer_propose {proposal}` -> новая карточка без применения.
`marketer_revise {id, revision, proposal}` -> новая версия указанной карточки.

Структура proposal: campaign_id, area, title, reason, expected_effect, success_metric, evaluate_after_days (14..90), action. Допустимые area: economics, search, rsya, creative, landing, assortment, experiment, measurement.

Примеры action:
```json
{"kind":"add_negative","ad_group_id":123,"phrase":"полный нерелевантный запрос"}
{"kind":"ad_text","ad_id":456,"fields":{"Title":"Новый заголовок"}}
{"kind":"strategy_value","side":"Search","field":"Cpa","value_micros":1100000000}
{"kind":"advisory","task":"Один конкретный ручной эксперимент"}
```

Для минусации необходимы >=20 зрелых кликов, числовой ноль по покупке и всем собранным целям стратегии. Перед записью отчёт перечитывается для защиты от поздних конверсий. Утверждение «слово нерелевантно» не выводится автоматически из словаря.

## Эксплуатация

Рабочая папка VPS: `/home/appuser/.openclaw/workspace/yandex-direct-bot`.
Службы пользователя: `yandex-direct-backend` (127.0.0.1:8091), `yandex-direct-marketer` (127.0.0.1:8092), единственный `openclaw-gateway`. Второй Telegram poller не запускается.

Приватные ключи: `~/.config/yandex-direct-bot/marketer.json` и `backend.env`, права 600. Токен Telegram берётся только из существующей конфигурации OpenClaw. Секреты, SQLite, экспорты и логи не входят в Git.

Аналитик direct-marketer имеет `tools.deny=["*"]`, отдельный контекст каждого анализа и не может выполнять команды/отправлять Telegram/менять кампании. Интерактивный direct сохраняет прежние инструменты; это не OS-изоляция от процесса того же Unix-пользователя.

GPT-5.4 перестала приниматься существующей ChatGPT-авторизацией. Для direct/direct-marketer настроена проверенная GPT-5.6 Terra через прежний openai-codex OAuth, без API-ключа. Остальные агенты и их настройки не меняются. Совместимый каталог задаёт консервативный контекст 128k, это лимит интеграции, не заявление о полном лимите модели.

Тесты:
```bash
cd backend
python3 -m unittest discover -s tests -q
node --experimental-strip-types ../integrations/yandex-direct-marketer/test.mjs
```

Установка: `python3 deploy/install_marketer.py`; `python3 deploy/configure_model.py`; после проверки аналитика `python3 deploy/configure_model.py --direct`. Недельный timer включается отдельно только после smoke-проверки. Источник плагина bridge теперь сохранён в репозитории, исправлена передача подтверждения create_campaign.

Проверка без записей в Директ: `python3 deploy/smoke_marketer.py collect`, затем `status`. `analyze` вызывает модель, но не отправляет карточки. `publish` отправляет только уже проверенные предложения, никогда не применяет их. Ручные smoke-команды не запускать параллельно с анализом службы.

## Резервная копия и откат

Перед установкой создана приватная копия `/home/appuser/backups/yandex-direct-20260919T124854Z`:
workspace.tar.gz (код, git, состояние, исходные изображения; без генерируемых exports/logs/venv), openclaw.json, bridge.

Откат проводить отдельно от рекламных изменений: остановить/отключить marketer.timer и marketer.service, остановить backend; сохранить текущие runtime и конфигурацию; восстановить архив workspace и конфигурацию/bridge из копии; перезапустить один gateway и один backend. Не удалять runtime: это журнал одобрений. Восстановление кода не отменяет уже применённые изменения в Директе.
